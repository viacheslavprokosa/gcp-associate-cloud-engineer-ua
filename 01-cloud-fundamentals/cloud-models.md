# Моделі хмарних обчислень

## Що таке хмарні обчислення?

**Хмарні обчислення (Cloud Computing)** - це надання обчислювальних ресурсів (серверів, сховищ, баз даних, мереж, програмного забезпечення) через Інтернет на основі оплати за використання.

## Основні моделі обслуговування

### IaaS (Infrastructure as a Service)

**Інфраструктура як сервіс** - провайдер надає віртуалізовану обчислювальну інфраструктуру.

#### Детальний опис

IaaS - це найбазовіша модель хмарних обчислень, яка надає віртуалізовані обчислювальні ресурси через Інтернет. Провайдер керує фізичною інфраструктурою (сервери, мережеве обладнання, системи зберігання даних), а користувач отримує повний контроль над віртуальними машинами, операційними системами та додатками.

#### Що надає провайдер

- **Віртуалізація** - гіпервізор для створення VM
- **Сервери (VM)** - віртуальні машини різних конфігурацій
- **Сховища** - блокові, об'єктні, файлові системи
- **Мережі** - VPC, підмережі, firewall, load balancers
- **Фізична інфраструктура** - датацентри, охолодження, живлення
- **Базова безпека** - фізична безпека датацентрів, мережева ізоляція

#### Що керує користувач

- **Операційна система** - вибір, встановлення, патчі, оновлення
- **Middleware** - веб-сервери (Apache, Nginx), application servers
- **Runtime** - Java, Python, Node.js середовища
- **Додатки** - ваш код та конфігурація
- **Дані** - бази даних, файли, backup стратегія
- **Безпека додатків** - firewall rules, шифрування, access control

#### Приклади в GCP

- **Compute Engine** - віртуальні машини з повним контролем
  - Різні machine types (E2, N2, C2, M2)
  - Custom machine types
  - Preemptible/Spot VMs для економії
  
- **Cloud Storage** - об'єктне сховище для будь-яких даних
  - Standard, Nearline, Coldline, Archive класи
  - Глобальна доступність
  - Lifecycle management
  
- **Persistent Disk** - блокове сховище для VM
  - SSD та HDD варіанти
  - Snapshots для backup
  - Можливість resize без downtime

#### Коли використовувати IaaS

- ✅ **Lift-and-shift міграція** - перенесення існуючих додатків у хмару без змін
- ✅ **Повний контроль** - потрібна специфічна конфігурація ОС або kernel modules
- ✅ **Legacy додатки** - старі системи, які не можна модифікувати
- ✅ **Тестування та розробка** - швидке створення середовищ з різними ОС
- ✅ **Високопродуктивні обчислення (HPC)** - наукові розрахунки, рендеринг
- ✅ **Compliance вимоги** - потрібен контроль над всіма аспектами інфраструктури

#### Переваги IaaS

- 🎯 **Максимальна гнучкість** - повний контроль над конфігурацією
- 💰 **Економія на CAPEX** - немає потреби купувати обладнання
- 📈 **Швидке масштабування** - додавання ресурсів за хвилини
- 🔧 **Підтримка legacy** - можливість запускати старі системи
- 🌍 **Глобальне розгортання** - датацентри по всьому світу

#### Недоліки IaaS

- ⚠️ **Висока складність** - потрібні DevOps навички
- 🔧 **Управління ОС** - відповідальність за патчі та оновлення
- 💸 **Можливі перевитрати** - якщо не оптимізувати ресурси
- ⏱️ **Довший час розгортання** - порівняно з PaaS

#### Приклади використання в реальному світі

**Сценарій 1: E-commerce платформа**

```text
Компанія має legacy e-commerce систему на власних серверах.
Вирішення: Міграція на Compute Engine VMs
- Мінімальні зміни в коді
- Збереження існуючої архітектури
- Економія на обладнанні
```

**Сценарій 2: Data Science лабораторія**

```text
Університет потребує потужних серверів для ML експериментів.
Вирішення: Preemptible VMs з GPU
- Оплата тільки під час використання
- Доступ до потужних GPU (NVIDIA A100)
- Швидке масштабування для різних проектів
```

**Сценарій 3: Disaster Recovery**

```text
Компанія хоче backup інфраструктуру для критичних систем.
Вирішення: Snapshots та standby VMs в іншому регіоні
- Автоматичні snapshots дисків
- Швидке відновлення при збоях
- Оплата тільки за storage snapshots
```

#### Вартість та оптимізація

**Моделі ценообразування:**

- **On-demand** - оплата за секунду використання
- **Committed Use Discounts** - знижки 37-57% за 1-3 роки
- **Sustained Use Discounts** - автоматичні знижки за тривале використання
- **Preemptible/Spot VMs** - до 80% знижки для fault-tolerant workloads

**Поради з оптимізації:**

- 💡 Використовуйте rightsizing recommendations
- 💡 Вимикайте dev/test VM поза робочим часом
- 💡 Використовуйте preemptible VMs для batch processing
- 💡 Налаштуйте autoscaling для змінного навантаження
- 💡 Використовуйте committed use discounts для production

### PaaS (Platform as a Service)

**Платформа як сервіс** - платформа для розробки та розгортання додатків без управління інфраструктурою.

#### Детальний опис

PaaS надає повне середовище для розробки, тестування та розгортання додатків. Провайдер керує всією інфраструктурою, операційною системою, middleware та runtime, дозволяючи розробникам зосередитися виключно на коді додатку та даних. Це значно прискорює розробку та зменшує операційні витрати.

#### Що надає провайдер

- **Все з IaaS** + додатково:
- **Операційна система** - автоматичні оновлення та патчі
- **Middleware** - веб-сервери, application servers
- **Runtime середовище** - Java, Python, Node.js, Go, PHP
- **Автоматичне масштабування** - horizontal та vertical scaling
- **Load balancing** - розподіл навантаження
- **Моніторинг та логування** - вбудовані інструменти
- **CI/CD інтеграція** - автоматичний deploy

#### Що керує користувач

- **Додатки** - ваш код та бізнес-логіка
- **Дані** - структура даних, контент
- **Конфігурація додатку** - environment variables, settings

#### Приклади в GCP

- **App Engine** - PaaS для веб-додатків
  - Standard Environment (обмежені runtime, швидкий старт)
  - Flexible Environment (Docker контейнери, більше контролю)
  - Автоматичне масштабування до нуля
  - Вбудований load balancing
  
- **Cloud Functions** - serverless функції
  - Event-driven архітектура
  - Оплата тільки за виконання
  - Підтримка HTTP triggers, Pub/Sub, Storage events
  - Автоматичне масштабування
  
- **Cloud Run** - контейнери без управління інфраструктурою
  - Будь-який Docker контейнер
  - Serverless або GKE backend
  - Швидкий cold start
  - Автоматичне HTTPS

#### Коли використовувати PaaS

- ✅ **Швидка розробка** - MVP, стартапи, proof of concept
- ✅ **Веб-додатки** - API, сайти, мобільні backend
- ✅ **Мікросервіси** - невеликі незалежні сервіси
- ✅ **Event-driven архітектура** - обробка подій, webhooks
- ✅ **Автоматичне масштабування** - змінне навантаження
- ✅ **Мінімальний DevOps** - невелика команда

#### Переваги PaaS

- ⚡ **Швидкий time-to-market** - deploy за хвилини
- 🔧 **Менше управління** - не потрібно керувати ОС
- 📈 **Автоматичне масштабування** - від 0 до тисяч екземплярів
- 💰 **Оплата за використання** - немає idle ресурсів
- 🔄 **Вбудований CI/CD** - легка інтеграція з Git
- 🛡️ **Безпека** - автоматичні патчі та оновлення

#### Недоліки PaaS

- ⚠️ **Vendor lock-in** - прив'язка до платформи провайдера
- 🔒 **Обмежена гнучкість** - не всі runtime підтримуються
- 💸 **Вища вартість** - порівняно з оптимізованим IaaS
- 🚫 **Обмеження** - розмір пакету, час виконання, dependencies

#### Приклади використання в реальному світі

**Сценарій 1: Стартап MVP**

```text
Стартап хоче швидко запустити веб-додаток для тестування ідеї.
Вирішення: App Engine Standard
- Deploy за 5 хвилин
- Автоматичне масштабування
- Оплата тільки за трафік
- Фокус на продукті, не на інфраструктурі
```

**Сценарій 2: Обробка зображень**

```text
E-commerce платформа потребує resize зображень при завантаженні.
Вирішення: Cloud Functions з Cloud Storage trigger
- Автоматична обробка при upload
- Оплата тільки за виконання функції
- Не потрібно керувати серверами
- Масштабування під будь-яке навантаження
```

**Сценарій 3: API для мобільного додатку**

```text
Компанія розробляє мобільний додаток з REST API backend.
Вирішення: Cloud Run з Docker контейнером
- Використання існуючого Docker image
- Автоматичне HTTPS
- Глобальний load balancing
- Масштабування до нуля коли немає запитів
```

#### Вартість та оптимізація

**Моделі ценообразування:**

- **App Engine**: Instance hours + outgoing traffic
- **Cloud Functions**: Invocations + compute time + memory
- **Cloud Run**: CPU/Memory usage + requests

**Поради з оптимізації:**

- 💡 Використовуйте App Engine Standard для масштабування до нуля
- 💡 Оптимізуйте cold start час (мінімізуйте dependencies)
- 💡 Використовуйте Cloud Functions для event-driven tasks
- 💡 Налаштуйте min/max instances для контролю витрат
- 💡 Використовуйте caching для зменшення compute time

### SaaS (Software as a Service)

**Програмне забезпечення як сервіс** - готове програмне забезпечення, доступне через браузер.

#### Детальний опис

SaaS - це модель, де провайдер надає повністю готовий програмний продукт. Користувачі отримують доступ до додатку через веб-браузер або API, не турбуючись про інфраструктуру, платформу чи саме програмне забезпечення. Провайдер відповідає за все: від серверів до оновлень додатку.

#### Що надає провайдер

- **Все з PaaS** + додатково:
- **Додатки** - готове програмне забезпечення
- **Оновлення** - автоматичні оновлення функціональності
- **Підтримка** - технічна підтримка користувачів
- **Інтеграції** - готові інтеграції з іншими сервісами
- **Backup та відновлення** - автоматичне резервне копіювання

#### Що керує користувач

- **Використання додатку** - робота з інтерфейсом
- **Дані користувача** - контент, файли, налаштування
- **Конфігурація** - обмежені налаштування (теми, preferences)
- **Управління користувачами** - додавання/видалення користувачів

#### Приклади

**Google Workspace:**

- **Gmail** - електронна пошта з 15GB безкоштовного storage
- **Google Drive** - хмарне сховище файлів
- **Google Docs/Sheets/Slides** - офісні додатки
- **Google Meet** - відеоконференції
- **Google Calendar** - календар та планування

**Інші GCP SaaS:**

- **Google Cloud Console** - управління GCP ресурсами
- **BigQuery** - data warehouse (частково SaaS)
- **Looker** - business intelligence платформа

#### Коли використовувати SaaS

- ✅ **Стандартна функціональність** - email, CRM, офісні додатки
- ✅ **Швидкий старт** - потрібно почати працювати негайно
- ✅ **Немає IT команди** - малий бізнес, стартапи
- ✅ **Collaboration** - команда працює разом над документами
- ✅ **Доступ з будь-де** - віддалена робота
- ✅ **Передбачувані витрати** - фіксована підписка

#### Переваги SaaS

- 🚀 **Миттєвий старт** - реєстрація та використання
- 💰 **Низька вартість входу** - немає початкових інвестицій
- 🔄 **Автоматичні оновлення** - завжди остання версія
- 🌐 **Доступність** - з будь-якого пристрою з браузером
- 👥 **Collaboration** - спільна робота в реальному часі
- 🛡️ **Безпека** - провайдер відповідає за security

#### Недоліки SaaS

- 🔒 **Мінімальна кастомізація** - обмежені можливості налаштування
- 📊 **Контроль даних** - дані зберігаються у провайдера
- 🌐 **Залежність від Інтернету** - потрібне постійне з'єднання
- 💸 **Довгострокова вартість** - підписка може бути дорожчою
- 🔗 **Інтеграції** - обмежені можливості інтеграції

#### Приклади використання в реальному світі

**Сценарій 1: Малий бізнес**

```text
Невелика компанія (10 співробітників) потребує email та офісних додатків.
Вирішення: Google Workspace
- $6-18/користувач/місяць
- Email, Drive, Docs, Meet
- Немає потреби в IT адміністраторі
- Автоматичні backup
```

**Сценарій 2: Віддалена команда**

```text
Стартап з розподіленою командою по всьому світу.
Вирішення: Google Workspace + Slack + Asana
- Collaboration в реальному часі
- Доступ з будь-якої точки світу
- Інтеграція між сервісами
- Масштабування разом з ростом команди
```

**Сценарій 3: Data Analytics**

```text
Компанія потребує аналізувати великі обсяги даних.
Вирішення: BigQuery + Looker
- Готова data warehouse платформа
- Не потрібно налаштовувати інфраструктуру
- Оплата за запити
- Готові візуалізації в Looker
```

#### Вартість та оптимізація

**Моделі ценообразування:**

- **Per-user subscription** - фіксована ціна за користувача
- **Tiered pricing** - різні плани з різною функціональністю
- **Usage-based** - оплата за використання (BigQuery)
- **Freemium** - базовий план безкоштовно

**Поради з оптимізації:**

- 💡 Використовуйте freemium плани для малих команд
- 💡 Оцініть реальну кількість активних користувачів
- 💡 Виберіть річну підписку для знижки (10-20%)
- 💡 Використовуйте інтеграції замість кількох окремих сервісів
- 💡 Регулярно переглядайте ліцензії неактивних користувачів

## Моделі розгортання

### 1. Public Cloud (Публічна хмара)

- Ресурси належать хмарному провайдеру
- Доступні для всіх через Інтернет
- Приклад: GCP, AWS, Azure

### 2. Private Cloud (Приватна хмара)

- Ресурси для однієї організації
- Може бути on-premises або у провайдера
- Більший контроль та безпека

### 3. Hybrid Cloud (Гібридна хмара)

- Комбінація публічної та приватної хмари
- Дані можуть переміщуватися між хмарами
- Гнучкість у розміщенні workloads

### 4. Multi-Cloud (Мульти-хмара)

- Використання кількох хмарних провайдерів
- Уникнення vendor lock-in
- Вибір найкращого сервісу від кожного провайдера

## Переваги хмарних обчислень

### 💰 Економія коштів

- **CAPEX → OPEX**: Перехід від капітальних витрат до операційних
- Оплата тільки за використані ресурси (pay-as-you-go)
- Немає витрат на підтримку власних датацентрів

### 📈 Масштабованість

- **Vertical Scaling**: Збільшення ресурсів VM (більше CPU, RAM)
- **Horizontal Scaling**: Додавання більше екземплярів
- Автоматичне масштабування на основі навантаження

### 🌍 Глобальна доступність

- Розгортання в різних регіонах світу
- Зменшення латентності для користувачів
- Відповідність локальним вимогам (data residency)

### 🔒 Надійність та відмовостійкість

- Резервування даних у кількох зонах
- Автоматичне відновлення після збоїв
- SLA гарантії доступності (99.9%, 99.95%, 99.99%)

### ⚡ Швидкість та гнучкість

- Швидке створення ресурсів (хвилини замість тижнів)
- Експериментування без великих інвестицій
- Легке видалення непотрібних ресурсів
